# Results

Generated by the scripts named in each section; regenerate rather than edit. Tracked in git as evidence, along with the API memos CI replays from.

Naming: `<cache>_<mode>__<model>_t<threshold>__<content>`. Files without a model/threshold cover all of them.

## Exact cache (`python3 -m cache.replay_exact`)

| File | Contents |
|---|---|
| `exact__per_query.csv` | One row per query: hit or miss, outcome vs `expected_cache`, which row it was served from, tokens saved |
| `exact__summary.json` | Totals: hits, false hits, missed repeats, recall, precision, tokens saved |

## Semantic cache (`.venv/bin/python -m cache.replay_semantic`)

Exact cache runs first; the semantic cache handles what it misses. Each mode adds checks to the one before:

| Mode | Checks before serving a cached answer |
|---|---|
| `cosine_only` | query cosine ≥ threshold |
| `cosine_context` | + the cached answer's docs and case are in the new request's context |
| `cosine_context_numbers_negation` | + same numbers/codes, + same negation count in the words that differ |

| File | Contents |
|---|---|
| `semantic_<mode>__bge-small_t0.90__per_query.csv` | One row per query at that model and threshold: layer (exact/semantic/llm), outcome, `miss_reason` (which check rejected it), cosine, served-from row |
| `semantic_<mode>__bge-small_t0.90__summary.json` | Totals for that run: paraphrases caught, wrong hits per trap type, traps stopped and paraphrases blocked per check, tokens saved |
| `semantic_<mode>__threshold_sweep_all_models.csv` | The same totals at every threshold 0.70–0.99, for bge-small and MiniLM |
| `semantic_mode_comparison__bge-small_t0.90.csv` | One row per mode, side by side: the improvement from each added check |
| `embedding_pair_cosine_all_models.csv` | Cosine between each paraphrase or trap and the query it imitates, per model (no cache involved) |

Outcomes: `correct_hit` (served answer has the right `answer_id`), `wrong_hit` (served a different answer), `missed_hit` (should have hit, went to the LLM), `true_miss`.

Tokens saved count correct hits only.


## End-to-end cost vs quality (`.venv/bin/python -m e2e.run [--data eval/data/evalset]`)

Baseline (Sonnet 5.5, full context) vs the pipeline variants; every answer graded by Sonnet 5.5 against the reference. `e2e__*` is the 150-query tuning set, `e2e_evalset__*` the 40-query held-out set.

| File | Contents |
|---|---|
| `e2e{,_evalset}__cost_vs_quality_summary.csv` | One row per pipeline: total cost, cost vs baseline, correct/partial/wrong share, mean score, cache hits, model split |
| `e2e{,_evalset}__quality_by_layer.csv` | Quality and cost per pipeline, layer and model |
| `e2e{,_evalset}__per_query_all_pipelines.csv` | Every answer: layer, model, tokens, cost, verdict, grader's reason |
| `e2e__api_memo.json` | Every answer and grade, keyed by a hash of the full request, so re-runs and CI replay without API calls |
| `judge_verdicts_haiku-4-5.json` | Memoized semantic-cache judge verdicts |

## Trace replay (`.venv/bin/python -m replay.trace`)

| File | Contents |
|---|---|
| `trace_replay_evalset__per_query.csv` | The held-out set sent through the running service in replay mode: layer (checked against the offline run), cost vs baseline, quality verdict, latency |

## Load test (`.venv/bin/python -m loadtest.run`)

| File | Contents |
|---|---|
| `loadtest__summary.csv` | Per run: traffic type (trace mix or all cold misses), concurrency, throughput, p50/p95/p99, errors |
| `loadtest__latency_by_layer.csv` | The same percentiles per layer |
